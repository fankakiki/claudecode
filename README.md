# 抢课回流票监控

两个版本，按需要选：

| 文件 | 说明 |
|---|---|
| **`qiangke.py`** | **macOS 单文件版，推荐。** 零依赖（只用标准库，Mac 自带 python3 直接跑），把两段 cURL 粘进文件顶部就能用，抢到弹系统通知 |
| `sjtu_grab.py` | 通用版。cURL 存成独立文件，支持多目标、并发提交、JSON 配置，需要 `pip install requests` |

原先的 Selenium 方案有几个硬伤：页面只在每 ~60 秒才真正刷新一次（其余时间在读过期 DOM）、
两段式确认弹窗判定错误、单轮 2~5 秒。而回流票的窗口期常常不到 1 秒。
接口版单轮 **几十毫秒**，这个差距比其他所有优化加起来都重要。

## qiangke.py 快速上手（macOS）

### 1. 抓两段包

选课页面按 **⌘⌥I** 打开开发者工具 → **Network** → 勾 **Fetch/XHR**。

- **①查询**：点一次页面上的「查询」，找到 Response 里能看见课程名的那条请求 →
  右键 → Copy → **Copy as cURL**
- **②提交**：在目标课程（此刻满员）上点一次「选课」让它失败 →
  那条请求 → Copy as cURL

> ② 必须是目标课程本身的提交请求。请求体里的教学班号已经是对的，
> 脚本原样重放即可，不需要理解学校接口的任何字段。

### 2. 粘进文件

打开 `qiangke.py`，把两段分别粘到顶部 `QUERY_CURL` / `SUBMIT_CURL` 的三引号中间，
确认 `KEYWORD` 是你的课程号。

### 3. 先探测，再开跑

```bash
python3 qiangke.py --probe     # 核对余量数字和页面上一致
python3 qiangke.py --watch     # 只看不抢，跑几分钟确认读数稳定
python3 qiangke.py             # 正式开抢
python3 qiangke.py --at 12:30  # 定时开抢（整点放票场景）
```

`--probe` 会打印匹配到的课程记录、余量是怎么算出来的、以及提交请求长什么样。
**务必确认余量数字和选课页面显示的一致再开抢。**

## 设计要点

- **共用长连接**：查询和提交同域时复用同一条连接。轮询把它一直焐着，
  真要提交时省掉 TCP+TLS 握手 —— 那几百毫秒正好花在最关键的一刻。
- **先判失败再判成功**：很多系统失败时也返回 `"code":"1"`，只看 code 会把失败当成功。
- **命中后 burst 重试**：发现余量立刻连打 3 次（间隔 150ms），不等下一个轮询周期。
- **不碰退选接口**：只重放你给的那条提交请求。
- **掉登录立即告警**：识别 302 / 登录页 HTML / "请重新登录"，弹通知并退出，
  而不是继续空转。
- **空转告警**：连续找不到目标课程时在第 3/10/50 轮告警 —— 静默空转是抢不到课
  最常见也最难发现的原因。

## 排障

| 现象 | 处理 |
|---|---|
| `还没填 cURL` | 两段 cURL 没粘进文件顶部 |
| `登录态失效` | Cookie 过期，重新 Copy as cURL 更新 `QUERY_CURL` |
| `连续 N 轮没找到` | 抓的接口带了分页/筛选参数，目标课不在返回里。换一条 XHR 重抓 |
| `识别不出余量字段` | 照 `--probe` 打印的字段名，填顶部的 `CAPACITY_FIELD` / `SELECTED_FIELD` |
| 余量算反了 | 同上，显式指定字段 |
| TLS 证书校验失败 | python.org 版 Python 需双击一次 `Install Certificates.command` |
| 提交明明成了却判为失败 | 把真实响应贴出来，按它改顶部的 `SUCCESS_PATTERN` / `FAIL_PATTERN` |

## 两句话提醒

- 默认 1 秒间隔已经比人工快两个数量级。**不要再往下调** —— 触发学校风控反而彻底抢不到。
  脚本遇到 429/5xx 会自动指数退避。
- 抢到后以选课系统页面刷新的结果为准，不要只信日志那一行。
